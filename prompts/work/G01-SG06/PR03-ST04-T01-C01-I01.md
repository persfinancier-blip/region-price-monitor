# G01.SG06.PR03.ST04.T01.C01.I01

## Role
Implement the local desktop delivery/bootstrap path for G01 without changing marketplace semantics. This is a transport/launch convenience for operator validation, not a second source of truth.

## Goal
Provide a **double-click Windows launcher** that on first use creates a local Git checkout of `persfinancier-blip/region-price-monitor`, prepares the parser runtime, and on every later use safely updates that checkout from the configured implementation branch before launching the parser locally.

## Inputs
- repository URL `https://github.com/persfinancier-blip/region-price-monitor.git`;
- configured branch/ref for the implementation under test (default must be explicit and easy to change; do not silently follow an arbitrary branch);
- current Windows desktop delivery (`install.bat`, `parser/run_parser.bat`, `parser/core/requirements.txt`);
- SG06 non-interactive/interactive launch interfaces as implemented at execution time.

## Required behavior
1. One user-facing `.bat` entrypoint suitable for double-click on Windows.
2. First run:
   - verify `git` exists and fail with a human-readable message if absent;
   - create a predictable local application directory when no checkout exists;
   - clone the configured repository/ref there;
   - invoke/reuse the repository's supported installer/runtime setup rather than duplicating dependency knowledge when practical;
   - launch the parser after successful setup/update.
3. Subsequent runs:
   - verify the local directory is the expected Git repository/remotes;
   - `fetch` the configured remote/ref;
   - update only by a safe fast-forward/switch policy; never `reset --hard`, delete untracked files, or silently discard local edits;
   - if tracked local changes would block update, stop with an explicit `LOCAL_CHECKOUT_DIRTY` message and instructions rather than overwriting them;
   - after a successful update, run only the minimum environment refresh needed when dependency/installer files changed, then launch the parser.
4. Preserve runtime-local/user material across Git updates. In particular, update logic must not delete or commit local `.env`, `config.json`, Ozon/WB profiles/cookies, results, debug output, venv/runtime cache or other ignored secret/state paths.
5. Never print proxy passwords, PostgreSQL passwords, personalized Ozon cookies/tokens, or authenticated URIs.
6. Do not require GitHub Actions, Docker, archive copying, or manual `git pull` for normal use.
7. If repository access later becomes private, fail clearly with an authentication instruction compatible with Git Credential Manager / authenticated Git rather than embedding a PAT in the script.
8. Keep the Git repository as durable source of code. The launcher must not copy source files into a divergent non-Git shadow tree.

## Suggested UX
Conceptually:

```text
Double click: START_PARSER.bat
        |
        +-- no local repo -> git clone
        |
        +-- repo exists   -> git fetch + safe fast-forward
        |
        +-- environment missing/outdated -> installer/setup
        |
        `-- launch parser
```

Exact filenames/paths may follow repository conventions, but the user should need only the one double-click entrypoint after initial placement.

## Acceptance
- clean machine/local folder: first launch creates a valid checkout and reaches parser launcher;
- second launch after a new remote commit updates to that commit and launches;
- no network/code change case does not destructively recreate the environment;
- dirty tracked checkout is not overwritten and yields explicit stop;
- local ignored runtime secrets/profile/results survive update byte-for-byte;
- wrong remote/repository directory fails safely;
- Git missing and authentication failure are human-readable;
- no credentials are embedded in repository/script/log output;
- existing `install.bat` / `parser/run_parser.bat` behavior is reused or deliberately adapted, not forked into an unrelated installer;
- tests may use a temporary local bare repository to prove first-clone, fast-forward update, dirty-tree stop and state-preservation without hitting production GitHub.

## Output Contract
A tested local bootstrap/sync launcher plus concise operator README/instructions. It transports the current Git implementation to the user's Windows PC, updates it safely on every launch, and starts the parser.

## Failure Boundary
Do not modify WB/Ozon parsing, ProxyContext semantics, RunPlan, persistence schemas, SG05 authenticated-cookie semantics, or create a scheduler service. If local delivery requires weakening `.gitignore` secret protection or destructive Git operations, stop with `LOCAL_DELIVERY_SAFETY_MISMATCH`.
