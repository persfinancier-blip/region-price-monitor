# G01.SG06.PR01.ST02.T01.C01.I01

## Role
Implement only reconciliation of collector outcomes against an accepted RunPlan. Do not reinterpret marketplace business semantics.

## Goal
Guarantee exactly one terminal accounted outcome for every planned semantic key even when collectors return partial, duplicate, unexpected or empty results.

## Inputs
- accepted `RunPlan` from PR01.ST01;
- accepted typed SG03 WB outcomes;
- accepted typed SG04 Ozon outcomes.

## Actions
1. Index collector outcomes by exact `(marketplace, sku, city)` key.
2. Preserve an accepted typed outcome when it maps uniquely to one planned key.
3. If a planned key receives no outcome, synthesize an explicit `missing_outcome` orchestration failure for that key.
4. If more than one terminal outcome maps to one planned key, emit an explicit duplicate/accounting failure rather than choosing one silently.
5. Treat an outcome for an unplanned key as explicit orchestration/accounting finding and do not silently enlarge the run matrix.
6. Verify terminal accounted count equals planned count.

## Output Contract
`AccountedOutcomeSet` with exactly one terminal record for each RunPlan key plus separate explicit unexpected-key findings where applicable.

## Acceptance
- `terminal_count == planned_count`;
- collector `[]`, exception, partial batch or missing SKU cannot shrink terminal set;
- every terminal failure keeps marketplace/SKU/city;
- valid WB zero stock remains business success/data and is not rewritten as missing/error;
- SG02/SG03/SG04 typed failures remain distinguishable.

## Evidence
Fixtures for complete success, partial batch, empty collector output, duplicate result key, unexpected key and mixed marketplace failures.

## Failure Boundary
Do not change SG03 stock semantics, SG04 city verification, transport error taxonomy, persistence schema, scheduler or fallback behavior.
