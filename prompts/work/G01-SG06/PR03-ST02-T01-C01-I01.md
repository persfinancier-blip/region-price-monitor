# G01.SG06.PR03.ST02.T01.C01.I01

## Role
Implement only the non-interactive/scheduler-ready primary entrypoint and configuration selection. Do not implement a scheduler daemon/service.

## Goal
Allow the complete primary run to start from configured product/city sources and output targets without any `input()` or legacy regional preparation.

## Inputs
- accepted SG01 product/city source adapters;
- accepted SG06 runner/orchestration boundary;
- existing config/env conventions including PostgreSQL env support;
- configured output target (file, PostgreSQL, or both).

## Actions
1. Provide arguments/config/env selectors for product source and city source using accepted SG01 adapters.
2. Provide non-interactive configuration for file output directory and PostgreSQL output; reuse existing env conventions where sensible.
3. Route execution into SG06 RunPlan -> primary collectors -> reconciliation -> persistence.
4. Ensure primary path never calls `load_sku_list`, `choose_output`, `wizard_connect`, `review_profiles`, `repair_regions`, `add_new_regions`, manual `get_wb_dest`, legacy `warm_region`, or any other `input()` flow.
5. Define deterministic process exit semantics: fatal config/plan/persistence failure != completed run containing unit-level marketplace failures.
6. Keep existing desktop interactive CLI available if useful, but make it a separate explicit mode rather than scheduler prerequisite.

## Output Contract
One documented command/module entrypoint that can execute a configured primary run to completion non-interactively.

## Acceptance
- zero `input()` calls on the scheduler-ready path;
- product file/DB and city file/DB sources remain selectable without code edits;
- file/PG/both output selectable without prompts;
- no legacy profile/cookie/dest preparation prerequisite;
- scheduler needs only launch the command/process;
- secrets such as PG/proxy passwords are not printed.

## Evidence
Subprocess/CLI tests that fail if stdin is requested; argument/config fixtures for source/output combinations; exit-code tests for unit failures versus fatal configuration/persistence errors.

## Failure Boundary
Do not add cron/systemd/Windows Task Scheduler provisioning, modify marketplace semantics, or introduce automatic SG05 fallback.
