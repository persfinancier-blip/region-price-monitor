# G01.SG06.PR02.ST03.T01.C01.I01

## Role
Implement only idempotent PostgreSQL schema/persistence support for canonical RunResultSet using existing ParserDB.

## Goal
Make PostgreSQL store every terminal planned unit without losing city, failure semantics or WB stock/availability.

## Inputs
- existing `parser/core/db.py` / `ParserDB`;
- complete canonical RunResultSet from PR02.ST01.

## Actions
1. Extend/migrate `parser_results` idempotently for required SG06 fields, preserving useful existing columns where compatible.
2. Ensure unambiguous `city` storage; legacy `region_code` may remain for compatibility but cannot be the only new primary identity if it is semantically incompatible.
3. Add/store `status`, `error_code`, `error`, `stock_qty` and nullable `is_available` semantics.
4. Write every RunResult row for one run_id; do not skip failures or rows with null price.
5. Remove current dangerous fallback behavior that would default failed/unknown rows to `is_available=True`.
6. Keep one run_id across the batch and return explicit persistence failure on transaction/schema error.
7. Use parameterized SQL and never serialize proxy/password/cookie secrets.

## Output Contract
Idempotently migrated ParserDB result schema + save/read path that round-trips the required semantic RunResult fields for a complete run.

## Acceptance
- repeated `_ensure_tables()` safe;
- existing database migration safe/idempotent;
- mixed success/failure rows round-trip;
- city/status/error and WB stock/availability survive;
- null failure values remain null, not invented defaults;
- row count for run_id equals planned count after successful persistence.

## Evidence
Database integration/migration tests against a disposable schema/database where available; deterministic SQL contract tests otherwise, with execution evidence required before acceptance.

## Failure Boundary
Do not redesign product/city input tables, collector semantics, file output, scheduler or fallback.
