# G01 / SG04 / PR01 / ST01 / T01 / C32.I01

## Goal
Reproduce the exact observed success shape from the standalone probe: one sticky mobile session, first Camoufox launch headless, second Camoufox launch visible, with no sticky rotation between launches.

## Contract
1. Load the cached local proxy from `parser/core/local/ozon_test_proxy.txt`.
2. Create exactly one fresh `hold-session-session-<id>` identity for the checkpoint.
3. Record its public egress IP.
4. Run Camoufox #1 headless on that exact sticky identity.
5. Keep the sticky identity unchanged after run #1 and re-check the public IP.
6. Run Camoufox #2 visible on the same exact sticky identity.
7. Observe full cookie counts/names, presence of `__Secure-ext_xcid`, UI challenge state, and browser-native Ozon API result for each run.
8. Re-check the sticky public IP after run #2.

## Acceptance
Primary PASS gate: `OZON_C32_SECOND_LAUNCH_PRICE_PROVEN`.

Diagnostic improvement gate: `OZON_C32_SECOND_LAUNCH_SESSION_IMPROVED` when the second launch obtains a larger/stronger cookie state even if price is not yet returned.

No-improvement gate: `OZON_C32_SECOND_LAUNCH_NO_IMPROVEMENT`.

## Evidence rationale
The previously successful standalone sequence used the same operator-provided sticky proxy across a failed headless run and an immediately following visible run. The second run yielded 9 cookies including `__Secure-ext_xcid` and the subsequent API request returned HTTP 200 with an exact SKU-bound price. C29-C31 did not reproduce this two-browser-launch sequence on one sticky identity.

## Safety / secrecy
- Cached proxy credentials stay local and gitignored.
- Cookie values are not printed or persisted.
- No CAPTCHA result submission, drag automation, pointer automation, or challenge-solving action is performed.
