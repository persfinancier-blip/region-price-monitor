# G01.SG04.PR01.ST02.T01.C02.I01

## Role
Compile accepted C02 runtime evidence into one explicit autonomous Ozon engine/context contract. Do not widen G01 silently.

## Goal
Define exactly how the primary Ozon path may establish and verify requested-city context without human browser work, while permitting hidden/headless Selenium/Chrome when evidence proves it necessary.

## Input
Accepted evidence from `G01.SG04.PR01.ST01.T01.C02.I01`.

## Actions
1. State which autonomous engine strategy is evidenced: `curl_cffi` only, hidden Selenium/Chrome only, or a bounded deterministic combination.
2. Define the exact engine selection/fallback order only from evidence; do not assume HTTP-first or browser-first when not proven.
3. Identify automatically created cookies/headers/browser/session state that may be reused or transferred between engines.
4. Define the exact acceptance signal for effective requested-city binding.
5. Define typed failures for engine unavailable, browser proxy binding unproven, context mismatch/unproven, anti-bot/session rejection and bootstrap failure.
6. Require every engine to consume the same SG02 ProxyContext authority; engine-specific proxy formatting may live in SG04 but may not create a second proxy source of truth.
7. If requested city cannot be verified from the minimum CityRecord/current Ozon behavior, output `OZON_REGION_CONTEXT_UNPROVEN`; do not invent fields or accept proxy geolocation as proof without evidence.

## Output Contract
One deterministic autonomous-engine/bootstrap/context-verification contract, or fail-closed `OZON_CONTEXT_CONTRACT_UNPROVEN`, `OZON_BROWSER_PROXY_BINDING_UNPROVEN` or `OZON_REGION_CONTEXT_UNPROVEN`.

## Acceptance
- hidden/headless browser is allowed; human interaction is forbidden in primary;
- no manual login, city/PVZ selection, visible-window prerequisite or manually maintained profile;
- no hidden mandatory CityRecord field;
- every rule traces to observed evidence;
- wrong/unverified region cannot be accepted as success.

## Failure Boundary
No networking implementation, price parsing, collector integration, persistence, scheduler or SG05 manual fallback redesign.
