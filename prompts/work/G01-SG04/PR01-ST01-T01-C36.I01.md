# G01 / SG04 / PR01 / ST01 / T01 / C36.I01

## Goal
Isolate whether the current Ozon bootstrap challenge is caused by the mobile-proxy path or reproduces in the same ordinary Playwright Firefox browser without the proxy.

## Contract
1. Use only stock Playwright Firefox for both arms.
2. Arm A: launch stock Firefox with no proxy and navigate to Ozon home.
3. Arm B: create one fresh sticky mobile proxy identity from the cached local credential and launch the same stock Firefox through it.
4. For each arm observe only:
   - main HTTP status;
   - final URL;
   - `window.isSecureContext`;
   - cookie count and cookie names;
   - presence of `__Secure-ext_xcid`;
   - challenge markers;
   - browser egress IP after the Ozon observation;
   - TLS security details when available.
5. Do not mutate UA, webdriver state, init scripts, fingerprint, headers, or browser preferences for either arm.
6. Do not submit, solve, or interact with CAPTCHA.

## Evidence / interpretation
- `OZON_C36_DIRECT_OK_PROXY_CHALLENGED`: direct stock Firefox reaches a materially healthier Ozon bootstrap while the proxy arm is challenged. This localizes the blocker to the proxy/egress path.
- `OZON_C36_DIRECT_AND_PROXY_MATCH`: both arms have the same material bootstrap outcome. The proxy is not sufficient to explain the block.
- `OZON_C36_DIRECT_DIFFERS_FROM_PROXY`: material outcomes differ in another way; inspect exact evidence before interpreting.

## Safety
- No CAPTCHA submission or interaction.
- No pointer/drag automation.
- No challenge-result endpoint.
- No anti-detect/fingerprint tuning.
- Proxy credentials and cookie values remain local/memory-only.
