# G01.SG04.PR01.ST01.T01 — C14.I01

## Input Contract
- One SKU.
- One city label and one explicit-scheme SG02 ProxyContext.
- Playwright/Chromium already installed by the existing dev bootstrap.
- No cookie file, login, password for Ozon, PVZ selection, second city or user interaction.

## Goal
Resolve the C13 ambiguity by testing normal headed Chromium **without the custom loopback browser bridge**. The browser must use Playwright's native proxy configuration derived directly from the same ProxyContext (`server`, `username`, `password`).

C13 already proved the headless browser could bind to the mobile proxy and Ozon returned a denial page, while the headed leg failed earlier in the local bridge with `ERR_TUNNEL_CONNECTION_FAILED`. C14 must not treat that bridge failure as Ozon evidence.

## Actions
1. Prove neutral egress through the SG02 curl adapter.
2. Launch Playwright Chromium with `headless=False` and native Playwright proxy settings derived from the exact same ProxyContext. Do not use `LocalBrowserProxyBridge`.
3. In the browser, fetch the neutral identity endpoint and require the same IP/location identity as curl.
4. Navigate to the requested Ozon product with JavaScript enabled and zero user interaction.
5. Observe whether the current Ozon entrypoint request for the exact SKU is emitted.
6. Record title/status and typed denial/captcha markers.
7. Save screenshot and browser storage-state only to the existing Git-ignored local probes directory. SAFE REPORT may contain cookie names/count, never values.

## Output Contract
SAFE REPORT must distinguish:
- native proxy binding success/failure;
- normal Chromium Ozon page status;
- Ozon denial/captcha vs loaded application;
- exact-SKU entrypoint observed vs not observed;
- cookie names/count only.

## Acceptance
`OZON_NATIVE_HEADED_ENTRYPOINT_OBSERVED` only when:
- curl neutral egress is proven;
- native Playwright proxy egress matches curl identity;
- no user interaction occurs;
- the exact current entrypoint request for the requested SKU is observed.

`OZON_NATIVE_HEADED_PAGE_LOADED_NO_ENTRYPOINT` when the Ozon product document loads without denial/captcha but the exact entrypoint is not observed.

## Failure Conditions
- `OZON_NATIVE_HEADED_PROXY_BINDING_FAILED`: native browser proxy cannot prove the same egress.
- `OZON_NATIVE_HEADED_BLOCKED`: same egress is proven, but Ozon returns denial/captcha.
- explicit Playwright/navigation/runtime failure.

No captcha solving or bypass is permitted. C14 is evidence only and remains outside production runtime.
