# G01.SG04.PR01.ST01.T01.C05.I01

## Role
Repair the Ozon runtime-evidence direction after owner review. Preserve the proven working reader instead of replacing it with a newly invented price-reading engine.

## Goal
Treat the already-working Ozon price reader as the canonical read baseline and separate its session/cookie bootstrap lifecycle from price retrieval.

## Proven working reader baseline
Repository/product delivery evidence already contains a working reader with these semantics:
- `curl_cffi` with `impersonate="edge"`;
- warmed Ozon cookie bundle;
- warm `GET https://www.ozon.ru/` through the same session/cookies;
- product `GET https://www.ozon.ru/product/<sku>/`;
- parse only the requested product's `state-webPrice-*` JSON embedded in HTML;
- price fields: `cardPrice`, `price`, `originalPrice`; availability field may be preserved as historical reader output but must not be confused with WB stock semantics;
- current G01 `parser/core/ozon.py` already adapts this reader's network calls to the shared SG02 `ProxyContext` and has no direct fallback.

## Accepted current evidence
- SG02 proxy path is proven: native curl + Requests + curl_cffi use the same explicit HTTPS ProxyContext and return identical Novosibirsk mobile egress.
- A separate cookie-free composer-api experiment returned HTTP 403. This proves only that the no-cookie composer experiment is blocked; it does NOT invalidate the proven cookie-backed product-HTML reader.

## Actions
1. Do not replace `parser/core/ozon.py` price-reading semantics with composer-only or browser-DOM price extraction.
2. Validate/use the proven `curl_cffi/edge + cookie bundle + product HTML + state-webPrice` reader through the SG02 ProxyContext.
3. Treat cookie/session acquisition and refresh as a separate bootstrap/lifecycle problem. A browser may be used only to create/refresh the technical session state that the proven reader consumes; browser use is not a replacement price reader unless a later explicit repair proves the reader unusable.
4. Keep bootstrap provenance explicit: existing/manual historical bundle, automatically-created fresh bundle, stale/rejected bundle. Never silently mix them.
5. A no-cookie 403 is not a reason to reject the proven reader and not a reason to invent another marketplace request path.
6. Record current live price evidence from the proven reader when a valid local cookie bundle is available. If no valid bundle exists, return an explicit bootstrap prerequisite rather than pretending the reader failed.
7. Preserve secret handling: cookie values stay local and never enter SAFE REPORT/GitHub; only bounded names/count/hash/provenance may be reported.

## Output Contract
One of:
- `OZON_PROVEN_READER_PRICE_EVIDENCE_CAPTURED` with bounded price fields and ProxyContext evidence;
- `OZON_SESSION_BUNDLE_REQUIRED` / `OZON_SESSION_BUNDLE_STALE_OR_REJECTED`;
- explicit transport failure through ProxyContext;
- later bootstrap evidence result, without replacing the reader semantics.

## Acceptance
- proven reader remains canonical baseline;
- same SG02 ProxyContext is the only proxy routing/auth authority;
- no direct fallback;
- no cookie values/secrets in report/repository;
- cookie bootstrap lifecycle is separated from price retrieval;
- no composer/browser replacement reader is accepted merely because a cookie-free experiment failed.

## Failure Boundary
Do not redesign WB, persistence, scheduler, RunResult, or SG05. Do not declare autonomous bootstrap complete without runtime evidence.
