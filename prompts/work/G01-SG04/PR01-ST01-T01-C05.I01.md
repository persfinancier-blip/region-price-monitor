# G01.SG04.PR01.ST01.T01.C05.I01

## Role
Repair the Ozon runtime-evidence direction after owner review. Reuse the already-proven ASocks/Ozon mechanism from the feasibility spike instead of replacing it with a newly invented price-reading path.

## Proven evidence baseline
Repository evidence records this working Ozon contour on ASocks:
- browser is used only to obtain/warm Ozon session/cookie state when needed;
- subsequent price read is lightweight `curl_cffi` with browser-like TLS impersonation and the warmed cookies;
- the proven spike reader targets the Ozon composer API for the requested product and parses only `webPrice`/`webSale` widget state;
- live evidence captured HTTP 200 and price fields for control SKU `3129447770`;
- changing Ozon regional state changed the observed price;
- plain/no-cookie HTTP returned 403 and does not invalidate the cookie-backed reader.

The shipped product later used the same architectural split (browser warm -> lightweight curl reader), with product-HTML `state-webPrice` parsing. Both forms support the same key conclusion: **price reading and session bootstrap are separate responsibilities; browser is not the steady-state price reader.**

## Accepted current evidence
- SG02 proxy path is proven: native curl + Requests + curl_cffi use the same explicit HTTPS ProxyContext and return identical Novosibirsk mobile egress.
- A cookie-free composer replay returned HTTP 403. This proves only that cookie-free access is blocked under current conditions.

## Goal
Reproduce the proven spike architecture through the current SG02 ProxyContext: automatically obtain fresh technical browser state through the same proxy, then perform the price read with `curl_cffi + cookies` using the proven Ozon request semantics.

## Actions
1. Use one bounded browser session through the exact SG02 ProxyContext only to create/warm technical Ozon session state. Do not treat browser DOM scraping as the canonical price reader.
2. Prove browser proxy binding before Ozon by matching the browser egress IP/location to the accepted SG02 transport egress.
3. No user login/PVZ/Enter/manual captcha in the primary evidence path. If Ozon demands human action, return a typed challenge result.
4. Extract browser-created cookie/session state in memory; cookie values may be written only to Git-ignored local evidence storage when required for the immediately-following reader replay, never to SAFE REPORT/GitHub.
5. After browser warm, perform the price request with `curl_cffi` through the same ProxyContext and the fresh cookies. Prefer the exact proven spike composer shape (`/api/composer-api.bx/page/json/v2?url=/product/<sku>/`) with browser-like headers and TLS impersonation; parse only bounded `webPrice`/`webSale` price fields.
6. Report bounded cookie names/count/provenance plus price fields/status. Never report cookie values or proxy credentials.
7. Treat no-cookie 403 as expected evidence motivating bootstrap, not as failure of the proven reader.
8. Keep regional verification separate: price evidence alone does not prove Ozon city if Ozon-side regional state cannot be observed.

## Output Contract
One of:
- `OZON_PROVEN_COOKIE_READER_PRICE_EVIDENCE_CAPTURED` with bounded price fields and browser/ProxyContext provenance;
- `OZON_BROWSER_PROXY_BINDING_UNPROVEN`;
- `OZON_BROWSER_HUMAN_ACTION_REQUIRED_CHALLENGE`;
- `OZON_SESSION_BOOTSTRAP_FAILED`;
- `OZON_SESSION_BUNDLE_STALE_OR_REJECTED`;
- explicit transport failure through ProxyContext.

## Acceptance
- proven browser-warm -> lightweight curl reader architecture is preserved;
- same SG02 ProxyContext is the only proxy routing/auth authority;
- no direct fallback;
- no manual human action in primary;
- cookie values/secrets never enter SAFE REPORT/GitHub;
- price parsing is bounded to the requested product price widget state;
- browser is not promoted to steady-state price reader.

## Failure Boundary
Do not redesign WB, persistence, scheduler, RunResult, or SG05. Do not declare Ozon regional binding complete without separate Ozon-side evidence.
