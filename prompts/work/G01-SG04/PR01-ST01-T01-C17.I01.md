# G01.SG04.PR01.ST01.T01 — C17.I01

## Input Contract
- One explicit-scheme mobile proxy gateway with credentials.
- One Ozon SKU.
- Up to 15 sticky session attempts.
- No Ozon cookie file.

## Goal
Answer the owner's direct question with live evidence: after selecting a known RU mobile sticky session, can the Ozon product entrypoint be parsed by a direct HTTP request alone?

Flow:
`rotate sticky mobile session -> prove mobile operator -> SAME ProxyContext/session -> direct entrypoint-api?url=/product/<sku>/`.

No request to Ozon home, no product HTML request, no cookies, no browser.

## Actions
1. Reuse C16 sticky mobile selector and stop on MTS/Beeline/MegaFon/Tele2-T2/Yota.
2. Reconstruct the exact selected ProxyContext using the selected sticky session id.
3. Call the recovered Ozon `entrypoint-api.bx/page/json/v2` directly with recovered dweb headers and curl_cffi impersonation profiles.
4. Never supply cookies.
5. Distinguish normal product JSON from challenge JSON.
6. If product JSON is returned, bind the requested SKU and select price by `layout -> stateId -> widgetStates`; never first/global `webPrice`.

## Acceptance
`OZON_DIRECT_ENDPOINT_ZERO_COOKIE_DATA_ACCESS_PROVEN` only when the direct zero-cookie request returns HTTP 200 normal JSON and an exact product price can be bound.

Typed non-acceptance:
- `OZON_DIRECT_ENDPOINT_MOBILE_SELECTOR_FAILED`
- `OZON_DIRECT_ENDPOINT_ZERO_COOKIE_CHALLENGED`
- `OZON_DIRECT_ENDPOINT_O3_HEADERS_STALE`
- `OZON_DIRECT_ENDPOINT_PRODUCT_BINDING_FAILED`
- `OZON_DIRECT_ENDPOINT_JSON_WITHOUT_PRICE`
- `OZON_DIRECT_ENDPOINT_TRANSPORT_FAILED`

Windows: `tests/RUN_OZON_DIRECT_ENDPOINT_C17.bat`
