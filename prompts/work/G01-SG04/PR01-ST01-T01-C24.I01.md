# Immutable Prompt — G01.SG04.PR01.ST01.T01.C24.I01

## Goal
Validate that the repository-owned local Ozon slider solver proven by C23 is robust across multiple fresh live challenges, not just one successful sample. Run several independent fresh sticky-mobile challenge/image/solve contours in one operator invocation and save a local visual preview for every solved sample.

C24 is a robustness/validation cycle only. It must not submit a CAPTCHA answer or mutate Ozon challenge state.

## Input Contract
- One visible runtime proxy string: `host:port:user:pass` (or explicit scheme form).
- Optional Ozon SKU; default may reuse the accepted reference SKU.
- Existing repository-owned C23 components and solver.
- Default live sample count: 3; bounded operator override 1..5.

## Runtime Contract
For every sample, execute a fresh continuous contour:

`fresh sticky selection -> immediate same-session IP recheck -> live Ozon challenge -> captchaURL decode -> exact background/puzzle fetch -> local solver -> post-solve same-session IP recheck -> local preview`

No historical C18/C19 expected IP/session may be required.

## Implementation Contract
1. Ask for proxy credentials once per C24 invocation, not once per sample.
2. For each sample select a fresh accepted Russian mobile sticky session with existing `find_mobile_proxy()`.
3. Verify the selected public IP immediately before the Ozon challenge and again after image retrieval/solve. A sample with continuity loss cannot count as solved evidence.
4. Obtain the live zero-cookie Ozon challenge through the exact selected ProxyContext.
5. Decode exact embedded `is` background and `ps` puzzle URLs in memory with repository-owned parser.
6. Fetch and validate both images through the SAME ProxyContext.
7. Run `solve_piece_by_contour(piece, background)` with existing fail-closed semantics.
8. Save raw challenge/background/puzzle only under Git-ignored local evidence.
9. For every `ok=true` solve, save a `preview.png` that overlays the movable puzzle crop at the solver x/y and marks its bounding box. Preview is diagnostic evidence only.
10. Emit per-run operator/IP/image/solver metadata and aggregate solved count plus confidence min/max/mean.
11. `OZON_SOLVER_ROBUSTNESS_PASS` requires every requested sample to return `solver.ok=true` and preserve same-session IP continuity through the sample.
12. Partial success must be `OZON_SOLVER_ROBUSTNESS_PARTIAL`; zero successful samples must be `OZON_SOLVER_ROBUSTNESS_BLOCKED`.
13. Never submit `/abt/captcha/result`, emulate pointer trajectories, mutate challenge cookies/state, or claim restored Ozon entrypoint access.
14. No Selenium/Playwright/browser, external CAPTCHA solver API, Docker or managed unlocker.
15. Never persist proxy credentials, full challenge URL, cp token or full image URLs in SAFE report.

## Output Contract
- `tools/probe_ozon_solver_robustness_c24.py`
- `tests/test_wave2_ozon_solver_robustness_c24.py`
- `tests/RUN_OZON_SOLVER_ROBUSTNESS_C24.bat`
- SAFE report `parser/core/local/probes/ozon_solver_robustness_c24_report.json`
- per-run raw/preview evidence under `parser/core/local/probes/ozon_solver_robustness_c24/run_XX/`.

## Acceptance Criteria
Deterministic:
- aggregate classification requires all requested runs for PASS;
- partial results classify as PARTIAL;
- preview generation writes a valid PNG for a structured successful solve;
- source audit proves no historical C18/C19 report dependency and no challenge submission/trajectory automation;
- SAFE report contract includes explicit secret/full-URL/submission flags.

Live success gate:
- `OZON_SOLVER_ROBUSTNESS_PASS` — all requested fresh samples retain same sticky IP and solver returns `ok=true` for every live challenge.

## Failure Conditions
- one successful sample represented as multi-sample robustness proof;
- continuity loss counted as solver success;
- fabricated coordinates or confidence;
- challenge submission or pointer automation;
- browser/external solver dependency;
- credentials or full signed URLs persisted.
