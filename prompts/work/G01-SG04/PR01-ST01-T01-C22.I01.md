## Proven structure
The live C19 `captcha` query value contains a short opaque prefix followed by Base64. After bounded prefix discovery, the decoded text has exactly three logical fields: challenge version, challenge id, and a `cp:` token. The final colon-delimited segment of that token is Base64 JSON. The live JSON keys include `pp`, `cb`, `support_domain`, `origin_referer`, `ts`, `is`, and `ps`; `is` is the background image URL and `ps` is the puzzle image URL.

## Implementation Contract
1. Implement a clean-room parser under `parser/core/captcha/` from the proven structure above; runtime must not execute Ozon's JavaScript/VM to find image URLs.
2. Parse raw query values without converting literal plus signs to spaces.
3. Discover the short opaque prefix by bounded structural validation rather than hard-coding the observed prefix text.
4. Decode the final cp-token segment to JSON and validate `pp`, `is`, and `ps`.
5. Accept only HTTPS image URLs without embedded credentials. Keep full challenge URL, cp token, and image URLs memory-only; SAFE output stores host/path suffix/hash only.
6. Rebuild the exact C18 sticky proxy identity from runtime credentials and require the neutral public IP to remain exactly equal to the accepted C18 IP.
7. Fetch the exact `is` and `ps` URLs through the SAME ProxyContext with curl_cffi and preserve response bytes.
8. Validate both responses as real images using Pillow and save bytes only under Git-ignored `parser/core/local/probes/ozon_payload_c22/`.
9. Run `solve_piece_by_contour(piece, background)` and record the structured result. If low-confidence/ambiguous, fail closed; do not invent coordinates.
10. No challenge result submission, no `/abt/captcha/result`, no pointer-trajectory emulation, no Ozon cookie mutation, and no claim of restored entrypoint access in C22.
11. No browser, Playwright, Selenium, external CAPTCHA solver API, Docker, or managed unlocker.
