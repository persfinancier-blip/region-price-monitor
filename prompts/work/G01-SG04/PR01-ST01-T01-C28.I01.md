# G01 / SG04 / PR01 / ST01 / T01 / C28.I01

## Goal
Prove Ozon price retrieval with one exact Camoufox browser network stack from bootstrap through API request, eliminating browser-to-HTTP TLS fingerprint drift.

## Live evidence motivating C28
C27 proved selected sticky IP == Camoufox browser IP == curl_cffi IP and matching HTTP/2/Akamai fingerprint, but JA3/JA4 differed between Camoufox Firefox 152 and curl_cffi generic Firefox. C27 therefore stopped before contacting Ozon for the price.

## Contract
1. Select one fresh Russian mobile `hold-session-session-<id>` proxy identity.
2. Start one Camoufox browser using that exact bound proxy identity.
3. Verify browser public IP equals the selected sticky public IP.
4. Bootstrap Ozon in that same browser context.
5. Keep the complete browser cookie jar inside the browser context; do not transfer or flatten cookies.
6. Execute Ozon `entrypoint-api` and, if needed, `composer-api` using browser-native `fetch()` from that same browser context.
7. Therefore proxy identity, TLS/JA3/JA4, HTTP/2 stack, User-Agent, browser state and cookies all originate from the exact same browser process.
8. Parse only the exact requested SKU price using the existing strict Ozon parser contract.

## Acceptance
PASS only when:
- selected sticky IP == browser IP;
- Ozon API request is browser-native, with no curl handoff;
- exact requested SKU price is returned.

Gate: `OZON_BROWSER_NATIVE_PRICE_PROVEN`.

## Failure semantics
- Mobile proxy selection failure: explicit blocked gate.
- Browser IP mismatch: `OZON_C28_BROWSER_STICKY_IP_MISMATCH`.
- Browser-native Ozon challenge/no exact price: `OZON_BROWSER_NATIVE_NO_PRICE`.

## Security / evidence
- Proxy credentials stay memory-only.
- Browser cookie values stay inside the browser context and are not persisted or printed.
- No CAPTCHA submission, drag automation, pointer automation, or challenge-result endpoint is used.
