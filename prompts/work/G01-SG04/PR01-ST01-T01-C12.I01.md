# G01.SG04.PR01.ST01.T01 — C12.I01

## Purpose
Prove or fail closed on the minimum autonomous Ozon guest-session bootstrap using only `curl_cffi` through one SG02 ProxyContext.

C11 proved the supplied two-cookie state from the denied Playwright page is rejected by Ozon. C12 must not reuse that state as authority.

## Input Contract
- one Ozon SKU;
- one city label;
- one explicit-scheme SG02 ProxyContext;
- no cookie file;
- no second city/proxy;
- no browser, Playwright, Selenium, login/password, captcha solving or PVZ selection.

## Actions
1. Prove neutral egress identity through the supplied ProxyContext.
2. Create a brand-new empty `curl_cffi.requests.Session(impersonate="chrome")`.
3. Through the same ProxyContext, GET `https://www.ozon.ru/` using that Session and allow the Session to absorb any Ozon `Set-Cookie` values automatically.
4. Record only safe cookie metadata after warm-up: count and cookie names. Never persist cookie values.
5. Using the exact same Session and ProxyContext, GET `https://www.ozon.ru/product/<sku>/`.
6. Using the exact same Session and ProxyContext, GET `https://www.ozon.ru/api/entrypoint-api.bx/page/json/v2?url=/product/<sku>/` with the known dweb request shape.
7. Treat Ozon challenge JSON (`challengeURL`, `blockURL`, `incidentId`) as anti-bot, never as product JSON.
8. Product binding is proven only when a normal entrypoint payload is HTTP 200 JSON and `pageInfo.url`, when present, contains the requested SKU. Challenge payloads can never satisfy product binding.

## Acceptance / typed evidence
- `OZON_CURL_GUEST_BOOTSTRAP_AND_ENTRYPOINT_PROVEN`: neutral egress proven; empty Session obtains Ozon session state automatically; entrypoint is HTTP 200 normal JSON, not challenge JSON, and product binding passes.
- `OZON_CURL_GUEST_BOOTSTRAP_CHALLENGED_AT_HOME`: Ozon root itself is denied/challenged before a usable session is established.
- `OZON_CURL_GUEST_BOOTSTRAP_CHALLENGED_AT_PRODUCT`: root proceeds but product is denied/challenged.
- `OZON_CURL_GUEST_BOOTSTRAP_CHALLENGED_AT_ENTRYPOINT`: entrypoint returns 401/403/challenge JSON.
- `OZON_CURL_GUEST_BOOTSTRAP_O3_HEADERS_STALE`: HTTP 400 from entrypoint.
- `OZON_CURL_GUEST_BOOTSTRAP_PRODUCT_BINDING_UNPROVEN`: normal HTTP 200 JSON exists but cannot be bound safely to requested SKU.
- `OZON_CURL_GUEST_BOOTSTRAP_TRANSPORT_FAILED`: neutral/proxy transport failed.

## Evidence
SAFE JSON report plus local Git-ignored raw bodies. Safe report may include cookie names/count only, never values, authorization headers, proxy password or raw storage state.

## Failure Conditions
- a cookie file is required;
- a browser or human step is introduced;
- direct/no-proxy fallback occurs;
- challenge JSON is counted as valid product JSON;
- region comparison is performed before single-proxy access passes.
