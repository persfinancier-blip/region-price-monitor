# G01.SG04.PR02.ST01.T01.C02.I01

## Role
Implement only the repaired autonomous Ozon context engine defined by accepted PR01 C02 evidence.

## Goal
Create a reusable `OzonContext` for one CityRecord without manually prepared profile/cookies, using the evidenced autonomous engine strategy: `curl_cffi`, hidden/headless Selenium/Chrome, or a bounded deterministic combination.

## Inputs
- accepted PR01 C02 autonomous-engine/bootstrap contract;
- CityRecord;
- accepted SG02 ProxyContext and HTTP transport interfaces.

## Actions
1. Implement only the evidenced engine strategy; do not hard-code HTTP-first or browser-first unless PR01 proved that order.
2. For `curl_cffi`, use the accepted SG02 adapter and ProxyContext.
3. For hidden/headless Selenium/Chrome, configure browser networking from the **same ProxyContext authority**. Engine-specific proxy adaptation belongs here, but no independent raw proxy configuration may become semantic authority.
4. Browser execution must be non-interactive: no visible-window prerequisite, user login, manual city/PVZ selection, Enter prompt or human captcha solve.
5. Automatically issued browser/session cookies may be retained in memory or transferred to `curl_cffi` only when permitted by the accepted contract.
6. If browser proxy authentication/binding cannot be safely applied/proven, fail `OZON_BROWSER_PROXY_BINDING_UNPROVEN`; never silently make a direct browser request.
7. Bound browser lifetime, timeouts and retries; close child browser/driver processes on success and failure.
8. Preserve requested city identity separately from mutable session/browser state and redact secrets.

## Output Contract
`OzonContext` containing safe city identity, evidenced engine provenance, automatically created session/browser state needed downstream and typed bootstrap status; or explicit transport/browser/session/bootstrap failure.

## Acceptance
- no `ozon_profile_dir` or legacy `cookies.json` prerequisite;
- hidden/headless Selenium/Chrome is permitted and fully automatic;
- every network engine uses the CityRecord ProxyContext;
- no silent direct fallback;
- bounded retries/process lifetime;
- no human browser action;
- secrets absent from ordinary diagnostics.

## Failure Boundary
Do not weaken city-verification rules, parse price semantics, modify collector policy, SG05 manual fallback, persistence or scheduler.
