# G01.SG04.PR01.ST01.T01 — C10.I01

## Purpose
Prove or fail closed on the owner's original regionality hypothesis: for Ozon, the requested city is determined by the selected city-bound mobile ProxyContext, while the same anonymous guest session/cookie state is reused unchanged.

## Input Contract
- one Ozon SKU;
- one anonymous Ozon guest cookie/storage-state file reused byte-for-byte for both runs;
- ProxyContext A for city A;
- ProxyContext B for city B;
- both proxy contexts use explicit scheme and SG02 remains the only routing/auth authority.

## Actions
1. Load the same anonymous guest cookie state once. Do not login and do not mutate or replace it between city runs.
2. For ProxyContext A and B separately, prove neutral egress identity through curl_cffi.
3. Call `https://www.ozon.ru/api/entrypoint-api.bx/page/json/v2?url=/product/<sku>/` through curl_cffi + the same guest cookie state + Ozon dweb headers.
4. Require HTTP 200 + decodable JSON before any product/price interpretation.
5. Verify `pageInfo.url` refers to the requested SKU when present.
6. Select the product price widget through `layout -> stateId -> widgetStates`; never take the first `webPrice`/`webSale` candidate. If exact selection is impossible, fail typed as ambiguous.
7. Record only safe evidence: proxy egress city/IP, response status/shape, exact-SKU binding, trusted widget state id, normalized price fields, response hashes. Never persist cookie values or proxy credentials in Git/report.
8. Compare the two exact-SKU results. A different exact-SKU regional value with different proven city egress and identical guest cookie input is positive evidence that ProxyContext drives regional output. Equal prices are inconclusive, not evidence against regionality.

## Acceptance / Typed Evidence
- `OZON_PROXY_REGION_EFFECT_PROVEN`: both city calls are HTTP 200 JSON, both bind to the requested SKU with a trusted/unique product price widget, both proxy egress identities are proven and different, the same cookie-state hash was used, and at least one exact-SKU regional value differs.
- `OZON_PROXY_REGION_EFFECT_INCONCLUSIVE_SAME_VALUE`: both calls are valid but exact-SKU regional values are equal.
- `OZON_GUEST_SESSION_BLOCKED`: one or both calls are 401/403/antibot with the supplied anonymous cookie state.
- `OZON_O3_HEADERS_STALE`: HTTP 400 consistent with stale pinned frontend build headers.
- `OZON_PRODUCT_BINDING_UNPROVEN`: response cannot be bound to the requested SKU.
- `OZON_PRICE_WIDGET_AMBIGUOUS`: multiple conflicting price widgets exist without an exact layout/stateId binding.
- `OZON_PROXY_BINDING_UNPROVEN`: neutral egress identity missing or both proxy contexts resolve to the same city/IP when two distinct cities were expected.

## Failure Conditions
- login/password/PVZ/manual browser work is introduced;
- different cookie files are used for A and B;
- price is selected by first-match/global-ruble search;
- equal price is misrepresented as proof that region did not switch;
- direct/no-proxy fallback occurs.
