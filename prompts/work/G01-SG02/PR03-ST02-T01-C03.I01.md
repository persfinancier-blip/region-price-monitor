## Runtime finding requiring C03
Operator Windows live evidence after the HTTPS-proxy and visible-password repairs proved all three neutral transport paths worked: native curl HTTP 200, Python Requests HTTP 200, and curl_cffi HTTP 200. The diagnostic gate nevertheless blocked WB/Ozon because it used the presentation root `https://i.pn`, whose response shape varies by client/UA, and because earlier logic treated the human city label as semantic authority. The operator used label `nvs`; automated clients returned successful bodies that did not expose top-level egress fields, producing unproven identity.

Official i.pn documentation defines the stable JSON API as `https://api.i.pn/json/{query}` and states that when `{query}` is omitted the current client/egress IP is used. This is therefore an acceptance-probe defect, not a marketplace or provider failure.

## Input Contract
- accepted ProxyContext with explicit live proxy scheme;
- documented neutral JSON endpoint `https://api.i.pn/json/`;
- native curl, Requests and curl_cffi neutral outcomes;
- human `city` value is a display/config label, not runtime proof by itself.

## Output Contract
- bounded extraction of safe egress identity fields from the documented JSON response: query, countryCode, regionName, city, mobile, proxy, hosting;
- locally retained neutral response bodies under Git-ignored `parser/core/local/probes` for diagnosis;
- gate compares observed egress location across the three independent stacks;
- human city label mismatch is informational only and cannot block marketplace probes when observed egress agrees across all stacks;
- WB/Ozon probes start only after all three transports succeed and their observed egress locations agree;
- no credentials written to report/repository.

## Acceptance Criteria
1. Native curl + Requests + curl_cffi must all succeed through the same ProxyContext before marketplace work.
2. Parsed egress country/region/city from all three paths must agree with each other.
3. A label such as `nvs` must not be treated as transport/geolocation authority and must not fail an otherwise proven egress consensus.
4. Actual disagreement between observed stack egress locations remains fail-closed.
5. Incomplete/unparseable egress identity remains explicit `PROXY_IDENTITY_UNPROVEN`; no guessing.
6. Neutral probe uses the documented JSON API, never the i.pn presentation root.
7. No direct fallback, second proxy authority, credential logging, marketplace semantic widening or hidden browser implementation.

## Failure Conditions
- presentation root `https://i.pn` is used as the machine-readable neutral contract;
- human city label is again used as runtime routing/geolocation authority;
- one successful stack is enough to bypass failed/mismatched stacks;
- credentials enter safe report or committed artifacts;
- identity parsing failure is silently treated as PASS;
- WB/Ozon semantics are claimed before their own runtime gates.
