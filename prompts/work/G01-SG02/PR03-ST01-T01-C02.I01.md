# G01.SG02.PR03.ST01.T01.C02.I01

## Supersedes
`G01.SG02.PR03.ST01.T01.C01.I01` as active Prompt for Task #54. C01 remains immutable history.

## Role
Repair only the collector proxy-authority handoff discovered by whole-G01 reverse compilation. Do not take ownership of SG04 browser/context semantics.

## Goal
Bind current WB/Ozon HTTP calls to SG02 adapters while defining the durable rule that **all primary network engines derive proxy routing/auth from the same city-bound ProxyContext**, including a future SG04 hidden-browser adapter.

## Inputs
- accepted SG02 PR01 ProxyContext/TransportOutcome;
- accepted SG02 PR02 `requests` and `curl_cffi` adapters;
- current WB/Ozon HTTP call sites;
- active SG04 C02 contract allowing hidden/headless Selenium/Chrome.

## Required result
1. Current WB underlying HTTP calls use the SG02 `requests` adapter/ProxyContext.
2. Current Ozon `curl_cffi` HTTP calls use the SG02 `curl_cffi` adapter/ProxyContext.
3. SG02 does **not** require future SG04 hidden-browser traffic to pass through `curl_cffi`.
4. If SG04 uses hidden/headless Selenium/Chrome, its browser-specific proxy configuration must be derived from the **same SG02 ProxyContext** and must not create a second raw proxy/user/password authority.
5. A supplied ProxyContext can never silently fall back to direct networking in any primary engine.
6. SG02 remains transport authority only; SG04 owns browser startup, browser proxy adaptation, session/location bootstrap, requested-city verification and lifecycle.
7. Existing WB/Ozon marketplace parsers remain outside this Task.

## Tests/evidence
- spies proving current `requests` and `curl_cffi` calls consume the same ProxyContext;
- interface test proving SG04 can consume a safe browser-proxy projection/adaptation from ProxyContext without reading CityRecord secrets independently;
- negative test for browser/direct-network bypass contract;
- no credentials in diagnostics.

## Output Contract
One durable collector/engine proxy-authority boundary:
`CityRecord -> SG02 ProxyContext -> {requests adapter, curl_cffi adapter, SG04-owned browser adaptation}`.

## Acceptance
- exactly one proxy credential/routing authority;
- HTTP adapters remain SG02-owned;
- browser semantics remain SG04-owned;
- no requirement that browser network calls transit through curl_cffi;
- no direct fallback;
- no new CityRecord field.

## Failure Boundary
Do not implement SG04 hidden browser, WB stock/dest semantics, Ozon price/context logic, persistence, scheduler or SG05 fallback. If browser support genuinely requires a second proxy credential source, stop with `CROSS_SG_INTERFACE_MISMATCH`.
