## Runtime finding
Windows Wave 2 live probe showed:
- Requests reached the configured proxy but received HTTP tunnel `407 Proxy Authentication Required`;
- curl_cffi failed before marketplace semantics with `curl_cffi:InvalidURL` / libcurl error 3 while consuming the credential-bearing proxy URL.

## Goal
Repair only the curl_cffi proxy-auth transport mechanics and make the live gate distinguish provider credential failure from marketplace failure.

## Required result
1. Keep `ProxyContext` as the single proxy routing/auth authority.
2. For curl_cffi, use its supported single `proxy` parameter for the non-secret proxy URL and `proxy_auth=(username,password)` for credentials, rather than requiring libcurl to parse an embedded credential URL.
3. Direct and caller-owned Session paths use the same repaired mechanics.
4. No direct/no-proxy retry or fallback.
5. Add deterministic tests proving `proxy` + `proxy_auth` reach both curl paths and raw `proxy`/`proxies`/`proxy_auth` caller overrides remain forbidden.
6. Extend the live probe with neutral proxy connectivity checks through both Requests and curl_cffi before WB/Ozon so a `407` can be attributed to proxy credentials/provider rather than WB/Ozon.
7. Neutral probe output remains secret-safe and does not persist credentials.

## Acceptance
- deterministic repaired adapter tests PASS;
- curl_cffi no longer receives a generated credential-bearing proxy URI from the adapter;
- live report can distinguish proxy-auth/connectivity failure from marketplace contract failure;
- no credential leak and no second proxy authority.

## Failure boundary
Do not alter WB stock semantics, Ozon regional/session semantics, persistence, scheduler or SG05 fallback. If neutral proxy connectivity itself rejects credentials, report provider/auth failure and keep #60/#71 unproven.
