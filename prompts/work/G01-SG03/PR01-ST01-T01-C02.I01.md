## Runtime finding requiring C02
After SG02 proxy transport was proven across native curl, Requests and curl_cffi on the same Novosibirsk mobile egress, the current WB probe returned HTTP 200 with `products=[]` for SKU `629760017` using only `cards/v4/detail` with `dest` omitted.

Repository archive evidence predating G01 shows the same SKU was live-tested successfully with WB card endpoints and regional `dest`; the archived Novosibirsk seed contains `dest=-1075267`. Archived parser fixtures also show stock at `data.products[].sizes[].stocks[].qty`.

The new evidence task must therefore compare the current no-dest assumption against the previously proven request shapes rather than interpreting `products=[]` as zero stock/not-found.

## Input Contract
- accepted SG02 ProxyContext with live egress already confirmed;
- representative WB SKU(s), including historical control SKU `629760017` when available;
- explicit WB dest supplied by operator or bounded archived diagnostic dest `-1075267` for Novosibirsk evidence only;
- current and archived WB card endpoint forms.

## Actions
1. Probe `cards/v2/detail` and `cards/v4/detail` through the same ProxyContext.
2. For each endpoint probe both with `dest` and with `dest` omitted.
3. Preserve the same SKU, proxy identity and request headers across the comparison except for endpoint/dest dimension.
4. Save raw bodies only under Git-ignored local probe storage; safe report contains hashes, counts, keys and bounded stock evidence.
5. Record exact observed stock path(s), including `sizes[].stocks[].qty` when present, without inferring availability from price.
6. Treat HTTP 200 + empty products as an explicit response shape, never as proof of zero stock or product absence.

## Output Contract
A four-cell comparison matrix:
- v2 + dest;
- v2 without dest;
- v4 + dest;
- v4 without dest;
with transport outcome, product count, safe price sample, exact stock path/sample evidence and local-body hash/path.

## Acceptance Criteria
- all four variants are distinguishable in the safe report;
- exact endpoint and whether dest was supplied are recorded;
- positive stock evidence, if observed, is tied to exact JSON paths;
- no stock-from-price inference;
- no false success from `products=[]`;
- inability to prove positive/zero/malformed semantics keeps #60 fail-closed.

## Failure Conditions
- changing proxy authority or bypassing SG02;
- silently making archived Novosibirsk dest a new mandatory CityRecord field;
- treating archived fixture alone as current runtime proof;
- interpreting empty products as zero stock/not-found;
- widening into persistence/scheduler/Ozon work.
