# G01.SG03.PR01.ST01.T01.C08.I01

## Goal
After C07 proved server-side WB reachability, validate the owner-supplied current WB data endpoint through the same SG02 ProxyContext without Chrome and without copying browser secrets.

## Current owner-supplied endpoint
`https://www.wildberries.ru/__internal/u-card/cards/v4/detail`

Captured query shape:
- `appType=1`
- `curr=rub`
- `dest=<diagnostic dest>`
- `spp=30`
- `hide_vflags=4294967296`
- `hide_dtype=15`
- `mtype=257`
- `lang=ru`
- `ab_testing=false`
- `nm=<SKU>`

## Security boundary
Do not commit or replay owner-captured cookie values, anti-bot tokens, validation keys, device ids, or other secret/session values in the first attempt. Use only non-secret request-shape headers and SG02 ProxyContext credentials supplied at runtime.

## Actions
1. Confirm Requests egress through `https://api.i.pn/json/` using the same ProxyContext.
2. Request the current `www.wildberries.ru/__internal/u-card/cards/v4/detail` endpoint with the captured query shape and only non-secret browser-shaped headers.
3. Save raw response locally/Git-ignored.
4. If response is JSON, verify that the requested SKU is actually present in the payload. Do not call HTTP 200 alone data-access success.
5. Report bounded response status/content type/server/body hash/top-level keys and whether the requested SKU is found.
6. If blocked (including WB 498/WBAAS), report that explicitly. Do not silently add captured browser cookies/tokens.

## Acceptance
`WB_CURRENT_ENDPOINT_DATA_ACCESS_PROVEN` only when the endpoint response is successfully decoded as JSON and the requested SKU is found in the response payload through SG02 ProxyContext.

## Non-acceptance
- `WB_CURRENT_ENDPOINT_REACHABLE_BUT_BLOCKED`
- `WB_CURRENT_ENDPOINT_NON_JSON`
- `WB_CURRENT_ENDPOINT_JSON_WITHOUT_REQUESTED_SKU`
- proxy/transport failure

## Boundary
This cycle proves endpoint access only. Price-field and stock-field semantics remain separate follow-up work. Ozon is out of scope until the owner supplies its concrete data endpoint.
