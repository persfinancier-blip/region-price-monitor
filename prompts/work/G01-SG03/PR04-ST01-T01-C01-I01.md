# Immutable Prompt — G01.SG03.PR04.ST01.T01.C01.I01

## Task
Integrate the accepted WB request and parser/outcome boundaries into the real WB collector so every requested `sku × city` yields one typed WB outcome through the city's SG02 ProxyContext.

## Authority
Parent Task: `G01.SG03.PR04.ST01.T01`.
Prerequisites: accepted PR02 request path and PR03 parser/classifier.
Contract: `docs/development/G01/SG03/vertical.md`.

## Inputs
- SG01 WB ProductSet subset and CitySet;
- SG02 ProxyContext per city;
- optional `wb_dest` per city;
- accepted WB request/parser/outcome contracts.

## Actions
1. Replace the current collector condition that skips WB when `wb_dest` is absent.
2. For each city with WB products, construct the city ProxyContext and execute WB request batches through PR02.
3. Preserve `city`/region identity on every per-SKU success or failure outcome.
4. Feed successful HTTP responses through PR03 parsing/classification.
5. Ensure one SKU's semantic failure does not remove sibling SKU successes.
6. Do not call `warm_browser.get_wb_dest` in the primary path.
7. Handoff normalized WB outcomes to the existing downstream boundary without implementing SG06 persistence changes here.

## Acceptance
- with-dest city produces typed product outcomes;
- no-dest city is not skipped and request omits forced dest;
- both use the city's ProxyContext;
- zero stock remains a valid WB result;
- proxy/HTTP/parser failure remains explicit;
- primary path has no manual WB region selection prerequisite.

## Forbidden scope
Do not change Ozon, DB/result schema, CSV schema, scheduler or legacy fallback beyond preserving compatibility boundaries.

## Stop condition
The actual WB collector can account for every requested WB SKU/city as success or explicit typed failure using the new primary contracts.
