# G01.SG05.PR01.ST02.T01.C02.I01

## Role
Define only the primary-vs-legacy invocation boundary for SG05 C02.

## Goal
Ensure the new SG04 proxy-first mechanism never depends on the current legacy personalized authenticated Ozon cookies/profile, while explicit legacy mode may depend on them exactly as the working mechanism does.

## Inputs
Accepted PR01.ST01 C02 inventory + SG04 C02 primary contract.

## Actions
1. Define primary as independent from `review_profiles`, `repair_regions`, `add_new_regions`, `warm_region`, legacy `cookies.json`, `browser_fetch_prices`, and manual `get_wb_dest` preparation.
2. Define legacy Ozon fallback as intentionally invokable and allowed to require a valid personalized authenticated profile/cookie set.
3. Define invalid/expired legacy auth as an explicit legacy failure/maintenance condition, never an implicit anonymous downgrade.
4. Keep automatic fallback switching out of scope.
5. Keep all personalized cookies/tokens secret and outside CityRecord/result/evidence payloads.

## Output Contract
Deterministic primary-vs-legacy invocation and credential-boundary contract.

## Acceptance
- new proxy-first path has no personalized-cookie prerequisite;
- current fallback retains its authenticated-cookie prerequisite;
- no silent anonymous fallback;
- explicit operator intent gates manual legacy work;
- no new city fields.

## Failure Boundary
Do not redesign SG04 transport, add automatic fallback policy, or copy secret cookie/token values.
