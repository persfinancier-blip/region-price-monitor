# G01.SG05.PR02.ST02.T01.C02.I01

## Role
Preserve explicit operator maintenance/support tools for the current legacy regional mechanism.

## Goal
Keep legacy profile review/repair/add-region, authenticated Ozon `warm_region` login/profile creation, and manual WB dest discovery intentionally reachable without coupling them to the new proxy-first primary path.

## Inputs
Accepted SG05 PR01 C02 boundary + current `review_profiles`, `repair_regions`, `add_new_regions`, `warm_region`, `get_wb_dest` behavior.

## Actions
1. Preserve explicit operator entrypoints for legacy profile review/repair and region setup.
2. Preserve `warm_region` as the operator-assisted way to create/refresh a **personalized authenticated** Ozon profile/cookies set when needed by the current fallback.
3. Preserve manual `get_wb_dest` support as optional legacy tooling.
4. Keep all auth cookies/tokens secret and runtime-local.
5. Ensure none of these tools is called automatically by SG04 primary startup/collection.

## Output Contract
Explicit legacy maintenance/support capability for authenticated Ozon profile refresh and optional WB dest discovery.

## Acceptance
- authenticated legacy profile can be intentionally refreshed via user login;
- no real secret is committed/logged;
- missing `wb_dest` remains valid for primary;
- SG04 primary has no dependency on this maintenance path.

## Failure Boundary
Do not make legacy maintenance automatic, do not change CityRecord, and do not redesign primary marketplace logic.
