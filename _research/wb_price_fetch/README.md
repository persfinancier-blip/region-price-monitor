# wb_price_fetch — цены Wildberries по регионам

Запустил — получил таблицу цен по городам. Без браузера, без кук, без капчи, без человека.
Папка самодостаточная: копируется в любой проект, зависимость одна — `requests`.

```
wb_price_fetch/
├── wb_price.py      # весь механизм
├── cities.json      # 22 города с координатами, редактируется руками
├── sku.csv          # список товаров (marketplace,sku)
├── dest_cache.json  # появится после первого запуска
├── run_wb.bat       # двойной клик
└── results/         # CSV с результатами
```

## Почему WB проще Ozon

Регион задаётся **параметром `dest` в самом запросе**, а не сессией. Поэтому один процесс
опрашивает сколько угодно городов подряд, и ему не нужны ни прогретые куки, ни привязка к IP,
ни прохождение антибота. Прокси опционален — только если хочется, чтобы IP совпадал с городом.

Это ровно та половина продукта, которая может работать на сервере автономно уже сегодня.

## Как работает

```
город → координаты → geo-API WB → dest → batch-запрос цен → CSV
```

`dest` берётся у самого WB: `user-geo-data.wildberries.ru/get-geo-info` по координатам города,
нужное число лежит в поле `xinfo` строкой `dest=-1257786`. Раньше в проекте это делалось
браузером с человеком — теперь не нужно.

Результат кэшируется в `dest_cache.json`: `dest` меняется редко, дёргать гео каждый раз незачем.

## Запуск

Двойной клик по `run_wb.bat` — Москва, Новосибирск и Владивосток по `sku.csv`, CSV в `results\`.

Или руками:

```bash
pip install requests

python wb_price.py --list-cities
python wb_price.py --city msk --sku 629760017
python wb_price.py --all-cities --sku-file sku.csv --csv results
python wb_price.py --city msk --city nvs --sku-file sku.csv --json
python wb_price.py --city nvs --sku 629760017 --proxy host:port:user:pass
```

Полезное: `--refresh-dest` перезапрашивает `dest`, игнорируя кэш.

## Что на выходе

В консоли — две сводки, цены и остатки:

```
  Цена различается по городам:
    629760017: msk=2940, mrm=2940, vvo=2975  → разница 35 ₽ (1.2%)

  Остаток различается по городам:
    629760017: msk=16 шт/2 скл/2ч, vvo=3 шт/1 скл/29ч, mrm=0 шт/0 скл  ← нет в наличии: mrm
```

Формат остатка: `сколько штук / на скольких складах / за сколько часов доставят`.

## Остатки по складам

WB отдаёт склады, **привязанные к `dest`**: на один и тот же товар Москва и Владивосток
получают разные склады с разными остатками и разными сроками. Именно поэтому остаток —
такая же региональная величина, как цена.

Пишутся два CSV:

**`wb_prices_*.csv`** — строка на товар в городе, сводно:
`city, city_name, dest, sku, name, brand, price, price_base, price_total, price_wallet_est,
currency, qty, wh_count, wh_main, wh_main_qty, delivery_h, is_available, supplier, rating,
collected_at`

| Колонка | Что означает |
|---|---|
| `qty` | суммарный остаток по всем складам этого региона |
| `wh_count` | сколько складов обслуживают этот город |
| `wh_main` / `wh_main_qty` | склад с наибольшим остатком и его количество |
| `delivery_h` | самый быстрый срок доставки в часах |

**`wb_stocks_*.csv`** — строка на связку товар × город × склад:
`city, city_name, dest, sku, name, wh, size, qty, delivery_h1, delivery_h2, price, collected_at`

Здесь видно, какой конкретно склад держит товар для города и за сколько часов довезёт
(`delivery_h1` — быстрый вариант, `delivery_h2` — обычный). У товаров с размерами будет
по строке на каждый размер.

Если WB не отдал разбивку и прислал только сводное число, `qty` берётся из `totalQuantity`,
а детальная таблица не создаётся — скрипт скажет об этом прямо.

## Про цены

WB отдаёт суммы в копейках, внутри `sizes[].price`:

| Поле | Что это |
|---|---|
| `basic` | цена до скидки, зачёркнутая |
| `product` | цена продажи — это и есть `price` |
| `total` | итог с логистикой, если WB его даёт |

`price_wallet_est` — **оценка** цены с WB-кошельком, минус 2%. Отдельного поля в ответе нет,
поэтому это прикидка, а не факт; в отчётах так и помечено суффиксом `_est`.

## Два эндпоинта

WB переносил карточный эндпоинт, поэтому пробуются оба по очереди:

1. `www.wildberries.ru/__internal/u-card/cards/v4/detail` — свежий, снят из DevTools 11.08.2026
2. `card.wb.ru/cards/v4/detail` — классический

В выводе видно, который сработал. Если оба отдадут не-200, скрипт скажет это прямо,
а не вернёт пустую таблицу.

## Города

`cities.json` — 22 города с координатами. Добавить свой: любая строка вида

```json
"tmn": { "name": "Тюмень", "lat": 57.1522, "lon": 65.5272, "address": "Тюмень" }
```

Код города — как удобно, он используется в CSV и в аргументах `--city`.

## Прокси

WB регион берёт из `dest`, а не из IP, поэтому прокси **не обязателен**. Нужен он в двух
случаях: если хочется, чтобы IP совпадал с городом, и если домашний адрес начал упираться
в лимиты.

Данные из панели провайдера кладутся в `proxy.json` рядом со скриптом (файл в `.gitignore`):

```json
{ "host": "naos.srvgdy.com", "port": 443, "user": "логин", "password": "пароль" }
```

Либо одной строкой, если провайдер даёт готовую ссылку:

```json
{ "url": "http://логин:пароль@naos.srvgdy.com:443" }
```

Образец — `proxy.example.json`. Тем, кому удобнее аргументами:

```bash
python wb_price.py --proxy host:port:логин:пароль --city msk --sku 629760017
python wb_price.py --proxy-host naos.srvgdy.com --proxy-port 443 \
                   --proxy-user логин --proxy-pass пароль --city msk --sku 629760017
python wb_price.py --no-proxy --city msk --sku 629760017      # игнорировать proxy.json
```

### Проверка выходного IP

То же, что `curl i.pn`, только внутри скрипта:

```bash
python wb_price.py --check-proxy
```

Покажет адрес, город, оператора и признак мобильного:

```
    прокси: http://***@naos.srvgdy.com:443
    выходной IP: 85.235.188.194 · Novosibirsk · MTS PJSC · мобильный
```

Проверка идёт по трём сервисам подряд (`api.i.pn`, `ipwho.is`, `ipinfo.io`) — если первый
недоступен из мобильного пула, отработает следующий. При обычном запуске эта строка
печатается автоматически, когда прокси задан.

Пароль в выводе всегда маскируется: `http://***@host:port`.

### Расход трафика

Мобильные прокси тарифицируются по гигабайтам, поэтому расход считается за каждый прогон:

```
  Трафик: 146.8 КБ за 3 запросов (принято 146.6 КБ, отправлено 183 Б)
  На один товар в одном городе: 16.3 КБ | тем же составом ежечасно — 103 МБ в месяц
```

Считаются байты «по проводу»: берётся `Content-Length`, то есть уже сжатый ответ — именно
то, что тарифицирует провайдер. Вторая строка помогает прикинуть счёт заранее: видно,
во что обойдётся текущий состав товаров и городов при выбранной частоте.

Практический вывод из формата: один запрос забирает до 50 SKU, поэтому увеличение
списка товаров стоит почти бесплатно, а вот добавление города умножает трафик.

## Работа с базой (сервер)

Города, артикулы и результат могут жить в SQL. Файлы `cities.json` и `sku.csv` тогда не нужны.

```bash
python wb_price.py \
    --db-url postgresql://user:pass@host:5432/parser \
    --cities-table parser_cities \
    --sku-table parser_skus \
    --results-table parser_results \
    --all-cities
```

Подключение можно не писать в командной строке — оно берётся из `RPM_DB_URL` или из
привычных `PGHOST` / `PGPORT` / `PGDATABASE` / `PGUSER` / `PGPASSWORD`.

Источники комбинируются: города можно взять из таблицы, а SKU из файла, и наоборот.
Флаги `--city`, `--sku`, `--sku-file` продолжают работать вместе с таблицами.

### Какие колонки нужны

Схема не навязывается — имена колонок определяются автоматически, так что подходит
и к уже существующим таблицам. Регистр не важен.

**Таблица городов** — либо координаты, либо готовый `dest`:

| Смысл | Подходящие имена |
|---|---|
| код города | `code`, `city_code`, `city`, `region_code` |
| название | `name`, `city_name`, `title` |
| широта | `lat`, `latitude` |
| долгота | `lon`, `longitude`, `lng` |
| dest | `dest`, `wb_dest`, `dest_id` — если есть, гео-API не дёргается |
| активность | `is_active`, `active`, `enabled` — необязательно, выключенные пропускаются |

**Таблица артикулов:**

| Смысл | Подходящие имена |
|---|---|
| артикул | `sku`, `nm`, `nm_id`, `nmid`, `article` |
| площадка | `marketplace`, `mp`, `platform` — необязательно, фильтруется по `wb` |
| активность | `is_active`, `active`, `enabled` |

**Таблица результатов** создаётся сама, если её нет. Колонки те же, что в сводном CSV,
плюс автоинкрементный `id`.

Если нужной колонки не найдётся, скрипт скажет прямо, какие имена он ждал и какие
увидел в таблице, — гадать не придётся.

### Проверить без сервера

Драйвер PostgreSQL нужен только для боевого запуска (`pip install psycopg2-binary`).
Для проверки логики годится SQLite:

```bash
python wb_price.py --db-url sqlite:///test.db --cities-table parser_cities \
    --sku-table parser_skus --results-table parser_results --all-cities
```

## Ограничения, о которых стоит знать

* `card.wb.ru` — неофициальный эндпоинт. По правилам WB (раздел 9.9.6) такое использование
  не поощряется. Собираются только публичные цены и держится вежливый темп: 50 SKU в запросе,
  пауза между пачками, backoff при 429. Риск на стороне владельца.
* Скидка WB-кошелька точно из ответа не берётся, только оценивается.
* `dest` и город — вещи связанные, но не тождественные: WB считает `dest` по координатам
  точки, а не по названию города. Если нужна конкретная точка выдачи, поправь координаты
  в `cities.json` на её адрес.
