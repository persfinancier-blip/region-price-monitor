# G01 — почему не собирается в одно

Ветка `work/g01-implementation`, состояние на 12.08.2026 (HEAD `2672216`).
Только диагностика, ничего не правил.

## Итог одной фразой

Продукт и новая машинерия — это две разные программы. Всё, что построено за C13–C26
(ProxyContext, мобильная липкая сессия, entrypoint-ридер, солвер), живёт исключительно
в `tools/probe_*.py` и запускается вручную через `input()`. Продукт (`cli.py` / `collect.py`)
ходит старым путём и **не вызывает из этой машинерии ничего**.

Прокси в продукте задать физически негде: поля для него нет ни в меню, ни в записи региона.

---

## Карта: что где живёт

| | Продукт (`parser/core`) | Машинерия (`tools/`) |
|---|---|---|
| Вход | `run_parser.bat` → `cli.py` (меню) | `python tools/probe_*.py` + `input()` |
| Прокси | `region.get("proxy")` — **всегда None** | `ProxyContext` + `find_mobile_proxy` |
| Ozon | `ozon.fetch_price` → SG05 legacy HTML | `fetch_price_proxy_first` → SG04 entrypoint |
| Куки | `warm_browser.warm_region` (без прокси) | не используются вообще |
| Результат | CSV / PostgreSQL | JSON-отчёт в `local/probes/` |

Пересечение между колонками — только модуль `ozon.py`, и продукт использует из него
ровно ту функцию, которая к прокси-архитектуре отношения не имеет.

---

## Разрывы

### 1. Прокси негде ввести — продукт о нём не знает

`cli.py`, `add_new_regions()` и `repair_regions()` собирают запись региона так:

```python
region = {"code": code, "name": name}
...
region["ozon_profile_dir"] = prof
region["wb_dest"] = dest
```

Ключ `proxy` не записывается никогда и в меню не спрашивается. При этом и `cli.run_parsing()`,
и `collect.py` читают его:

```python
proxy = region.get("proxy")     # → None, всегда
```

Вся мобильная машинерия получает прокси только из `input("Proxy (VISIBLE host:port:user:pass): ")`
внутри проб. **Это и есть первая причина, почему «в одно» не собирается: продукт не имеет
входа для прокси.**

### 2. Продукт не вызывает SG04 ни разу

`collect.py` и `cli.run_parsing()` зовут только:

```python
res = ozon.fetch_price(sku, cookies, proxy=proxy, save_debug=(i == 0))
```

`ozon.fetch_price()` — это тонкая обёртка над `fetch_price_legacy_authenticated` (SG05).
`fetch_price_proxy_first` (SG04), `read_price`, `ProxyContext`, `curl_transport`,
`mobile_proxy` в продукте не импортируются вообще. Ни один `import` на них не ведёт
из `parser/core/*.py`, кроме самого `ozon.py`.

### 3. Две несовместимые схемы региона

Продуктовый `config.json`:

```json
{"code": "msk", "name": "Москва", "wb_dest": -1257786, "ozon_profile_dir": "...", "proxy": null}
```

Что требует `ProxyContext.from_city` → `normalize_city_record` (`input_models.py`):

```python
city           = _required_text(row.get("city"), ...)            # обязательное
proxy          = _required_text(row.get("proxy"), ...)           # обязательное
proxy_user     = _required_text(row.get("proxy_user"), ...)      # обязательное
proxy_password = _required_text(row.get("proxy_password"), ...)  # обязательное
```

Пересечения нет: в продуктовой записи нет ни `city`, ни `proxy_user`, ни `proxy_password`.
Передача региона из `config.json` в `ProxyContext.from_city` падает сразу с
`InputValidationError: required field 'city' is missing or blank`.

Плюс встречное требование — `ProxyContext.from_city` **запрещает** креды внутри строки:

```python
if parsed.username is not None or parsed.password is not None:
    raise ProxyContextError("proxy address must not contain embedded credentials")
```

а продукт кладёт прокси одной строкой и отдаёт её прямо в curl_cffi:

```python
proxies = {"https": proxy, "http": proxy} if proxy else None
```

То есть даже если заполнить `proxy` в `config.json` руками, SG04 его не примет.

### 4. SG04 не умеет принимать куки

```python
def fetch_price_proxy_first(sku, proxy_context: ProxyContext):
```

Параметра для кук нет, и внутри они не передаются. Путь жёстко zero-cookie —
это записано в докстринге как свойство контракта.

Следствие: SG04 **всегда** будет отдавать `status="challenge"` на живом Ozon, что твой
прогон C19 и показал (403 + `captchaURL`/`blockURL` на всех пяти стратегиях). Даже если
куки где-то появятся, скормить их основному пути нечем.

### 5. Куки греются без прокси

`warm_browser._new_driver()`:

```python
o = uc.ChromeOptions()
o.add_argument(f"--user-data-dir={profile_dir}")
o.add_argument("--disable-blink-features=AutomationControlled")
o.add_argument("--no-sandbox")
```

Ни `--proxy-server`, ни моста. Куки всегда снимаются с домашнего IP.
Если в продукте когда-нибудь появится прокси (разрыв 1), получится классика:
куки с IP «A», чтение с IP «B» → 403 независимо от свежести кук.

При этом мост уже написан и рабочий — `tools/browser_proxy_bridge.py`,
`LocalBrowserProxyBridge`: поднимает CONNECT-прокси на loopback и сам подставляет
`Proxy-Authorization` вверх по цепочке (именно потому, что Chrome не умеет
`user:pass@host` в `--proxy-server`). **`warm_browser.py` его не импортирует.**

### 6. SG05 в C26 прибит к `proxy=None`

`tools/probe_ozon_price_reader_c26.py`, `_try_legacy_profiles()`:

```python
legacy = ozon.fetch_price_legacy_authenticated(sku, cookies, proxy=None, save_debug=False)
```

Мобильная сессия к этому моменту уже выбрана и проверена — и не используется.
Профили при этом ищутся в том числе в старом чекауте `C:\Dev\region-price-monitor\parser\core`,
то есть куки заведомо с другого IP.

### 7. Детект протухших кук мёртв

`collect.py`:

```python
if "error" in res:
    if res["error"] == "403":
        stale.append((code, sku))
```

`ozon.py` больше не возвращает `error="403"` — теперь это
`{"status": "legacy_rejected", "error": "authenticated_session_rejected", "http_status": 403}`.
Условие не сработает никогда, список `stale` всегда пуст, предупреждение
«перепрогрей куки» не выводится. Оператор видит только `❌ authenticated_session_rejected`.

### 8. Слово «price» значит три разных вещи

| Путь | Что попадает в `price` |
|---|---|
| SG04 `_parse_entrypoint_price` | `widget["price"]` — обычная цена; карта отдельно в `price_card` |
| SG05 `parse_price` | `card or reg` — **приоритет у цены с картой** |
| `browser_fetch_prices` | число из DOM, оно же дублируется в `price_card`, `price_regular=None` |

Цены из разных путей в одной таблице сравнивать нельзя — разница между «обычной» и
«с Ozon-картой» на живых товарах доходит до 5–6 раз.

### 9. Регулярка SG05 хрупкая

```python
m = re.search(r'id="state-webPrice-[^"]*"\s+data-state=\'([^\']*)\'', html)
```

Ждёт `data-state` в **одинарных** кавычках и строго следующим атрибутом после `id`.
Любой другой порядок атрибутов или двойные кавычки → `None` → `status="parse_error",
error="200_no_price"`, при том что страница пришла нормальная.

### 10. Решение капчи никуда не уходит — и это осознанно

Во всех отчётах `challenge_submitted: false`, `captcha/protocol.py` метит любые
`verify/validate/submit/solve/check/confirm` как `risky_submission_like` и не трогает.
Солвер считает `x` и на этом цепочка заканчивается.

Это не баг, но это значит, что SG04 сам по себе из челленджа не выйдет никогда.
Единственный способ его разблокировать — куки живой сессии, полученные тем способом,
которым у тебя это исторически и работало: человек решает капчу один раз в браузере.

## Что уже готово и просто не соединено

| Деталь | Файл | Состояние |
|---|---|---|
| Браузер через прокси с авторизацией | `tools/browser_proxy_bridge.py` | готово, не подключено к `warm_browser` |
| Выбор мобильной липкой сессии | `tools/mobile_proxy.py` | готово, не подключено к продукту |
| Прогрев: логин + ПВЗ + карточка + автозакрытие | `parser/core/warm_browser.py` | готово, без прокси |
| Чтение цены через entrypoint | `ozon.fetch_price_proxy_first` | готово, без кук |
| Склейка SG04+SG05 за одним контрактом | `ozon.read_price` | готово, **никем не вызывается** |
| Продуктовый пайплайн CSV/PG | `collect.py`, `storage.py`, `db.py` | готово, ходит мимо всего вышеперечисленного |

Функция `read_price()` — ровно тот стык, который нужен. Её не вызывает ни один файл
в репозитории, кроме тестов.

## Минимальный порядок сборки

1. **Одна схема региона.** Решить, что канонично: `config.json` или `CityRecord`.
   Написать адаптер в одну сторону — `region → ProxyContext` (`city ← code`,
   `proxy_user`/`proxy_password` отдельными полями, без кред в строке).
2. **Поле прокси в меню.** `cli.add_new_regions` спрашивает прокси и пишет его в регион,
   иначе всё остальное бессмысленно.
3. **Прогрев через тот же прокси.** `warm_browser._new_driver` поднимает
   `LocalBrowserProxyBridge` из ProxyContext региона и отдаёт Chrome
   `--proxy-server=http://127.0.0.1:<порт>`. Человек решает капчу один раз — куки
   привязываются к тому же выходному IP.
4. **Куки в SG04.** Добавить `cookies=` в `fetch_price_proxy_first` и прокинуть в запрос.
   Тогда `read_price` наконец имеет смысл: primary с куками через тот же прокси,
   legacy — как запасной.
5. **Продукт зовёт `read_price`.** Заменить в `collect.py` и `cli.run_parsing`
   вызов `ozon.fetch_price` на `ozon.read_price` с ProxyContext региона.
6. **Починить мелочи:** детект 403 (разрыв 7), единый смысл `price` (8), регулярка (9).

Пункты 1–2 — без них ничего не поедет. 3–5 — собственно «сборка в одно».
6 — то, что иначе будет тихо портить данные.
