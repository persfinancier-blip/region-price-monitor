# Как сейчас парсят цены Ozon — разбор практики

12.08.2026. Смотрел GitHub (45 репозиториев, использующих эндпоинты Ozon), документацию Ozon
и отраслевые публикации.

---

## 1. Главный факт: официального пути нет, и это решение самого Ozon

**12 ноября 2025 Ozon отключил `marketing_price`** — параметр, через который продавец мог
получить хотя бы приблизительную витринную цену.

| Метод Seller API | Было | Стало |
|---|---|---|
| `/v5/product/info/prices` | `price.marketing_price` | **отключён 12.11.2025** |
| `/v3/product/info/list` | `items.marketing_price` | убран из ответа и документации |
| `/v2/posting/fbo/list` | `customer_price` | параметр удалён |

Сейчас по Seller API доступна только **своя цена продавца** — та, которую он сам туда и
передал. Цена, которую видит покупатель, официально недоступна **никак**: ни через
`marketing_price`, ни другими полями. Это подтверждено и на форуме разработчиков Ozon.

Я в прошлом сообщении советовал «посчитать официальный API» — снимаю совет, он был основан
на устаревшем представлении. Официального источника витринной цены не существует, даже для
собственных товаров продавца. Отсюда и весь рынок парсеров.

Практический вывод для тебя: выбор не между «парсить или взять по API», а между
**«парсить самому» и «купить у того, кто парсит»**.

## 2. Что реально работает — разбор живых репозиториев

### TimNekk/MarketplacesGoodsTracker — самая зрелая схема

Двухступенчатая, ровно та, к которой ты пришёл сам, но с важными отличиями:

```python
# ступень 1: сессия из анти-детект браузера, БЕЗ человека
with Camoufox(os="windows", headless="virtual", geoip=True, humanize=2.0) as browser:
    page.goto("https://www.ozon.ru/?__rr=1&abt_att=1")
    cookies = {c["name"]: c["value"] for c in page.context.cookies()}

# ступень 2: дальше лёгкие запросы с этими куками
tls_session.get(PRODUCT_URL + url_part, headers=..., cookies=...)
```

Что здесь принципиально:

- **Браузер headless и без человека.** Не потому что капчу решают автоматом, а потому что
  Camoufox её не вызывает: это отдельная сборка Firefox, где отпечаток правится на уровне
  браузера, а `geoip=True` подгоняет таймзону, язык и координаты **под IP прокси**.
- **`humanize=2.0`** — движения курсора с человеческой динамикой.
- **Транспорт — `tls_client`** с ротацией отпечатков `chrome_116…chrome_120`
  (аналог твоего `curl_cffi impersonate`).
- **Эндпоинт — `composer-api.bx`**, не `entrypoint-api.bx`. Оба живы, у тебя выбран второй.
- **Поведение при 403:** обновить сессию. А если и новая сессия ничего не собрала —
  **пауза 60 минут** перед следующей попыткой. Это самозащита от разгона бана.
- **Темп:** `sleep(random.randint(4, 6) + random.random() * 2)` — 4–8 секунд между товарами.
- Цена берётся из первого ключа `webPrice-*`: `price` и `cardPrice`.

### yyyJ8/Ozon_BI — гибрид «официальный API + браузер»

Китайский BI для продавца. Каталог, `offer_id`, `marketing_seller_price` — из официального
Seller API в PostgreSQL. А «зелёная цена» (то, что покупатель видит как «С банками») —
браузером через DrissionPage, потому что иначе её взять неоткуда.

- пауза между товарами — **15 секунд**;
- явная детекция блокировки по маркерам: `antibot captcha`, `abt-challenge`,
  `доступ ограничен`;
- цена извлекается инжектом JS в страницу, с полем `confidence` в результате.

Смысл: они не пытаются заменить официальный API парсером. Они парсят **только то одно поле**,
которого API не даёт.

### Shipovmax/parser_ozon — минимальный честный вариант

DrissionPage, отключены картинки, двойное извлечение: сначала из DOM, при смене вёрстки —
из JSON в исходнике страницы. Капча: **скрипт встаёт на паузу и ждёт человека**. Автор
это прямо пишет в README как штатное поведение.

### Общая картина по 45 репозиториям

- `entrypoint-api.bx/page/json/v2` и `composer-api.bx/page/json/v2` — оба в ходу;
- цена всегда из `widgetStates` → `webPrice-*` → `price` / `cardPrice` / `originalPrice`;
- голых `requests` без маскировки TLS нет ни у кого — не работает;
- `undetected_chromedriver` (то, что у тебя в `warm_browser.py`) в свежих проектах почти не
  встречается — вытеснен DrissionPage и Camoufox.

## 3. Единый паттерн отрасли

```
анти-детект браузер (один раз, headless, без человека)
        ↓ cookies + headers
лёгкий HTTP-клиент с маскировкой TLS (много запросов, вежливый темп)
        ↓ 403
новая сессия из браузера; если и она пустая — длинная пауза
```

Твоя архитектура совпадает с этим на 90%. Расходятся два места:

1. **Чем бустрапится сессия.** У тебя `undetected_chromedriver` + человек, решающий капчу.
   У них — анти-детект браузер, который капчу не вызывает.
2. **Что делать при 403.** У тебя — вилка в браузер к человеку. У них — новая сессия и
   пауза, всё автоматически.

Именно первый пункт закрывает твою проблему с автономностью на сервере, и закрывает **не**
через решение капчи, а через то, что проверка не срабатывает: браузер не выглядит поломанным.
Разница существенная — одно дело обойти проверку, другое дело не попадать под неё
из-за кривого отпечатка.

**Важная оговорка про Camoufox:** проект больше года без активной поддержки, база Firefox
устарела, в отпечатке нашли новые несостыковки — эффективность просела. Как готовое решение
брать рискованно, как ориентир по подходу — полезно. Живые альтернативы того же класса:
DrissionPage (используется в обоих серьёзных проектах выше), patchright, rebrowser-patches.

## 4. Регионы: этого не делает никто

Из всех просмотренных проектов **ни один не собирает цены по разным городам**. Все берут
цену «как получится», с домашнего IP, гостевой сессией. Поиск по коду
(`ADDRESSBOOKBAR`, `pickup`, `region` рядом с ozon) не дал ни одного совпадения.

Значит две вещи:

- готового рецепта, который можно скопировать, нет — это твоя специфика и, возможно,
  твоё конкурентное преимущество;
- проверять гипотезу «прокси задаёт город» придётся самому. Твой C10 —
  `probe_ozon_proxy_region_effect.py` — именно для этого и написан, и остаётся
  единственным способом получить ответ. **Посмотри в нём `gate`.**

Косвенно: `geoip=True` в Camoufox существует именно потому, что несовпадение
IP и таймзоны/локали — известный триггер антибота. У тебя сейчас мобильный прокси
Новосибирска и браузер с `timezone_id="Europe/Moscow"` — рассогласование, которое видно.

## 5. Коммерческие поставщики данных

Если считать стоимость своей разработки и поддержки:

- **MarketParser** — мониторинг витрины Ozon/WB/ЯМ/Мегамаркет/Kaspi, отдаёт цену покупателя,
  зачёркнутую, оценку с картой; хранит историю; до 150 обновлений в сутки; есть API,
  партнёрская и white-label схемы. Появился ровно на волне отключения `marketing_price`.
- **MPStats** — эталон по аналитике WB/Ozon/ЯМ, своя технология подсчёта продаж.
- **Apify Ozon Seller & Competitor Scraper** — готовый скрапер с API, платится за запуски.
- **MetaCommerce** — enterprise-платформа ценовой аналитики для крупного ритейла.

Отмечу: **Moneyplace, eCompass, SellerExpert, Anabar, Statberries закрылись.** Рынок
нестабилен, и это аргумент против того, чтобы вешать продукт на одного поставщика без
запасного варианта.

## 6. Что из этого стоит забрать в твой проект

| Что | Откуда | Зачем |
|---|---|---|
| Заменить `undetected_chromedriver` на DrissionPage | оба зрелых проекта | uc.Chrome сейчас детектится; это может убрать капчу как явление |
| Согласовать таймзону/локаль браузера с гео прокси | Camoufox `geoip=True` | сейчас у тебя рассогласование, это триггер |
| 403 → новая сессия + длинная пауза, а не вилка к человеку | TimNekk | делает сервер автономным |
| Пауза 4–15 сек между товарами | оба | ты сейчас идёшь без пауз |
| Пробовать `composer-api.bx` как запасной эндпоинт | TimNekk | второй путь на случай, когда первый закрыт |
| Поле `confidence` у извлечённой цены | Ozon_BI | у тебя есть `trusted` — та же идея, доведи до конца |
| Свериться с ценой из Seller API по своим товарам | Ozon_BI | единственная доступная проверка парсера на правду |

Последнее стоит подчеркнуть: если у тебя есть доступ к кабинету продавца хотя бы по части
товаров, `price` из Seller API — независимая опорная точка. Ей можно ловить ситуации, когда
парсер приносит цену чужого товара из карусели. Ту самую, что я нашёл в `test_pars_2`,
где один SKU дал 209, 2805 и 9446 ₽ за сутки.
