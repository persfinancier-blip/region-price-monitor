# Справка по Ozon — не текущая задача

Отложено. Сейчас работаем по WB (`промпт/парсер-wb.md`). Здесь только чтобы не

## Итог проверки: автономный сбор упирается в капчу

Проведён полный цикл. Воспроизведена эталонная конфигурация — Linux + Xvfb + анти-детект
браузер Camoufox + мобильный прокси МТС/Билайн/Tele2, согласованные UA и TLS. Ozon отдаёт
капчу на первом же контакте.

Исключены: отпечаток браузера, headless-режим, репутация адреса, рассинхрон IP,
TLS-профиль, выбор эндпоинта. Дальнейшее решение **нетехническое** — кодом это не дожимается.
Подробности — `ИТОГ-проверки-автономного-парсинга.md`.

Официальный Seller API витринную цену **не отдаёт**: `marketing_price` отключён 12.11.2025,
это осознанное решение площадки. Публичного API у Ozon нет.

## Матчасть, если вернёмся

- Цена лежит в **JSON виджета `webPrice`** внутри HTML, поле `cardPrice`.
- **Не искать цену общим поиском по ₽** — цепляются цены соседних товаров из рекомендаций.
  Один артикул за сутки давал 209, 2805 и 9446 ₽ в разных прогонах.
- Рабочий рецепт ручного прогона: без VPN, залогиненная сессия, прогрев с заходом на
  карточку, `curl_cffi` с профилем `edge`. Куки живут ~24 часа.
- Регион **зашит в куку**, не в параметр запроса — принципиальное отличие от WB, где регион
  идёт параметром `dest` и потому куки не нужны вовсе.
- Эталон рабочего механизма — `test_pars_2`. Когда версия v2 «не работала», причина была
  **в коде** (заменили `uc.Chrome` на Playwright, выкинули профиль `edge`), а не в окружении.

## Чего не делать

**Не решать капчу автоматически.** Это обход проверки, а не парсинг, и означает войну с
антиботом на каждом запросе.
