# Автономная сессия Ozon: что проверено и что из этого следует

12.08.2026. Здесь зафиксировано, что именно тестировалось, чтобы не проходить это заново.

## Задача

Получать цены Ozon на сервере без человека. Схема отрасли: анти-детект браузер один раз
поднимает сессию → куки → дальше лёгкие HTTP-запросы с маскировкой TLS.

## Что проверено

| Переменная | Эталонная реализация | У нас | Итог |
|---|---|---|---|
| ОС | Linux | Linux (WSL2 Ubuntu) | ✔ совпало |
| Окно браузера | `headless="virtual"` (Xvfb) | настоящий браузер в Xvfb через `xvfb-run` | ✔ совпало |
| Браузер | Camoufox | Camoufox v152.0.4-beta.28 | ✔ совпало |
| geoip | `geoip=True` | IP определяется снаружи и передаётся строкой | ✔ совпало |
| URL входа | `ozon.ru/?__rr=1&abt_att=1` | тот же | ✔ совпало |
| Ожидание API | `expect_request` | то же | ✔ совпало |
| Идентичность при запросе | Chrome UA + Chrome TLS | то же | ✔ совпало |
| Эндпоинт | `composer-api.bx` | оба, `entrypoint` и `composer` | ✔ шире |
| Прокси | нет | мобильный МТС/Билайн/Tele2, Новосибирск | ✚ добавлено |
| IP браузера = IP запроса | — | проверено, совпадают | ✔ |

Итого: воспроизведено всё, ни одного отличия по существу не осталось.

## Результат

Во всех прогонах одно и то же:

```
главная:  «Antibot Captcha» → АНТИБОТ
карточка: «Antibot Captcha» → АНТИБОТ
куки: 2 шт. вместо 15–25
запрос цены: HTTP 403, challenge
```

Ozon показывает проверку на **первом контакте**, до всякой работы с ценой. 403 на запросе —
следствие, а не отдельная проблема.

## Что это исключает

* **Не отпечаток браузера.** Camoufox в настоящем окне на Linux — потолок того, что даёт
  открытый инструментарий.
* **Не headless.** Проверено и так, и так.
* **Не репутация одного адреса.** Три оператора (Билайн, Tele2, МТС), несколько свежих
  адресов, все Новосибирск — капча мгновенно на каждом.
* **Не рассинхрон IP.** Браузер и `curl_cffi` выходят с одного адреса, проверено явно.
* **Не TLS и не эндпоинт.** До них дело не доходит.
* **Не прокси-канал.** Браузер через него открывает сторонние сайты нормально.

## Важная оговорка про эталон

Мы сверялись с открытым проектом (`TimNekk/MarketplacesGoodsTracker`), потому что он
выглядит зрелым. Но **доказательств, что он работает сегодня, нет**. Код на GitHub — это
не работающий сервис. За последний год Ozon заметно закрутил гайки: убрал `marketing_price`
из Seller API (12.11.2025), ввёл JSON-челлендж с `captchaURL`. Вероятно, мы догоняли поезд,
которого уже нет.

Косвенное подтверждение: даже в их коде при 403 предусмотрена пауза **60 минут** — то есть
капча ловилась регулярно и в их условиях.

## Что осталось непроверенным

Один вариант: сессия без прокси на Linux (`run_probe_wsl.bat --no-proxy`) — эталон работает
именно так. С оговоркой, что домашний адрес за день получил десятки заходов пробами C13–C26.

## Выводы

Автономная сессия без человека на сегодня не поднимается. Дальше выбор не технический:

1. **Человек в цикле.** Раз в сутки сессия поднимается на десктопе (логин, ПВЗ, карточка),
   куки уезжают на сервер, сервер молотит автономно. Сервер человека не ждёт — это ротация
   доступа, как с любым ключом. Механизм у нас уже описан и частично написан.
2. **Покупка данных.** MarketParser, MPStats и подобные держат эту войну как основной бизнес.
   Цена известна заранее, в отличие от бесконечной отладки.
3. **Отказ от Ozon в продукте.** WB работает полностью автономно — ни кук, ни капчи,
   регион задаётся параметром `dest`. Если WB закрывает задачу, Ozon можно вынести
   в отдельный платный тариф или убрать.

Чего делать не стоит: автоматически решать капчу. Это обход проверки, а не парсинг,
и вдобавок означает войну с антиботом на каждом запросе.
