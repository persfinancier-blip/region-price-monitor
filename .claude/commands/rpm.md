Прочитай `prompts/ТЕКУЩИЙ.md` и выполни его полностью, фаза за фазой, автономно.

Общие правила проекта — `docs/правила-работы.md`. Прочитай их до начала.

## Правила выполнения

- **Не останавливайся для подтверждений**, кроме случаев, когда промпт явно требует СТОП.
- Ход работы и итог каждой фазы **дописывай** в `prompts/РЕЗУЛЬТАТ.md` (создай, если нет).
  Не переписывай файл целиком — только добавляй в конец.
- Если что-то блокирует работу (нет доступа, упавшая среда, противоречие в промпте) —
  зафиксируй блокер в `prompts/РЕЗУЛЬТАТ.md` и остановись с коротким отчётом.
- Между фазами не спрашивай разрешения. Переходи сам.

## Фаза 0 — Подготовка

```bash
git fetch origin --prune
git checkout main
git pull --ff-only
git checkout -b task/<короткое-имя>-<ГГГГММДД-ЧЧММ>
```

Имя ветки выведи из задачи в `prompts/ТЕКУЩИЙ.md`, латиницей, через дефис.
Если ветка уже существует — продолжай в ней, новую не плоди.

Запиши в `prompts/РЕЗУЛЬТАТ.md` шапку: дата, имя ветки, одна строка о задаче.

## Фаза 1 — План

Не пиши код. Разберись:

1. Что уже есть в репозитории по этой теме. Читай, а не сочиняй заново.
2. Что именно требует промпт. Если требование неоднозначно — выбери трактовку,
   запиши её явно и иди дальше.
3. Разбей на шаги. Для каждого — как поймёшь, что он сделан.

Итог: список шагов и критерии готовности → в `prompts/РЕЗУЛЬТАТ.md`, раздел «План».

Если из архива нужен старый код — доставай, не переписывай с нуля:

```bash
git show archive-20260814:путь/к/файлу
git checkout archive-20260814 -- путь/к/файлу
```

## Фаза 2 — Код

Реализуй план. По ходу дела:

- Логика — в самостоятельных скриптах. Оболочка только принимает ввод и показывает вывод.
- Не трогай то, о чём не просили.
- Секреты не хардкодь. Всё, что похоже на ключ, прокси или пароль — в `.env`,
  в репозиторий кладётся только `.env.example`.

Коммить по ходу, мелкими осмысленными кусками, не одним «всё сразу».

## Фаза 3 — Проверка

**Не «должно работать», а запустил и показал вывод.** Без этого фаза не считается пройденной.

1. Запусти то, что написал. Реальный вывод — в `prompts/РЕЗУЛЬТАТ.md`, раздел «Проверка».
2. Прогони тесты, если они есть в проекте.
3. Проверь диф на секреты:

```bash
git diff --stat origin/main...HEAD
git diff --name-only origin/main...HEAD | Select-String -Pattern '\.env$|\.pem$|\.key$|cookie|credential|proxy.*\.(txt|json)$'
```

Если совпадения есть и это не `.example` — **СТОП**. Убери из истории ветки, зафиксируй в отчёте.

Честно напиши, что не работает. Полуработающее, названное рабочим, дороже несделанного.

**Фаза зелёная** = запуск показал ожидаемый результат, тесты (если есть) прошли,
секретов в дифе нет.

## Фаза 4 — Сдача

```bash
git add -A
git commit -m "<тип>: <что сделано>"
git push -u origin HEAD
gh pr create --fill --base main
```

Тип коммита: `feat`, `fix`, `docs`, `chore`, `refactor`.

Дальше по итогу фазы 3:

- **Фаза 3 зелёная** → мержим сами:

  ```bash
  gh pr merge --squash --delete-branch
  git checkout main && git pull --ff-only
  ```

- **Фаза 3 не зелёная** → PR оставь открытым, мерж не делай.
  В `prompts/РЕЗУЛЬТАТ.md` напиши, что именно не сошлось и что нужно решить.

Если `gh` не установлен или не авторизован — запиши это как блокер, ветку всё равно
запушь, и скажи в отчёте, что PR нужно открыть вручную.
